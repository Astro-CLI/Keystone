INVESTIGATION FINDINGS

CRITICAL DISCOVERY: Multiple .pkt Format Variants

Format A: Our Implementation
  ✓ Works for internal operations (can encrypt/decrypt)
  ✗ PT 8.2.2 rejects these files
  - Header: 4-byte uncompressed size
  - Payload: XOR-encrypted (key = size - position)

Format B: ptexplorer's Original Format
  ✗ Our files don't use this format
  ✗ Real Cisco files don't either
  - All bytes XOR-encrypted
  - Key = total_file_size - position

Format C: PT 8.2.2's Actual Format
  ❓ UNKNOWN
  ✗ Cannot decrypt real Cisco .pkt files
  ✗ Our format not compatible
  - Real Cisco files cannot be decrypted
  - Algorithm completely different

IMPLICATION: The reverse-engineering sources (ptexplorer/packetReader) may
have been documenting PT 5.x format, not PT 8.2.2 format.
