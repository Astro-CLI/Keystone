# פרק 4: אוטומציות ותכנות במהלך הפרויקט

## 4.1 ההקדמה

כשהתחלנו לממש את תשתית הענן של SOYMSA ב-Packet Tracer, הבנו במהירות שתיקוף ידני של עשרות התקנים יהיה בלתי אפשרי. דברנו על עשרות שעות של עבודה ידנית אם היינו צריכים להקליד כל פקודה בנפרד על כל נתב, מתג, חומת אש ושרת.

זה היה הרגע שבו החלטנו לבנות כלים אוטומטיים. בנינו סדרה של סקריפטים Python שיכלו ליצור תצורות רשת באופן אוטומטי. בפרק הזה אסביר מה בנינו, למה בנינו את זה, ומה למדנו בדרך.

## 4.2 הבעיה שעמדה בפנינו

הבעיה הבסיסית הייתה פשוטה: תיקוף רשת חוזר על עצמו שוב ושוב.

למשל, אם הייתי צריך להגדיר OSPF על 15 נתבים, בעצם אני עושה אותו דבר 15 פעמים:
- הגדרת כתובות IP בממשקים
- הפעלת OSPF
- קביעת מזהי הקטעים (Area IDs)
- בדיקה שהחיבוריות עובדת

לעשות את זה ידנית ב-Packet Tracer פירושו:
1. לחץ ימני על כל התקן
2. לחץ על "Configure"
3. הקלד כל פקודה בנפרד
4. בדוק אם זה עובד
5. חזור על זה לכל התקן

זה היה לוקח שעות. הייתי צריך דרך טובה יותר.

## 4.3 הפתרון שלנו: ארכיטקטורה מודולרית

בניתי את האוטומציה בשתי שכבות עיקריות:

**שכבה 1: מנתח פורמטים (format_parser.py)**

ראשית, יצרתי כלי שיכול לקרוא הגדרות רשת מפורמטים שונים. המשתמשים יכלו להגדיר את טופולוגיית הרשת שלהם ב-YAML, JSON, או XML - איזה שהוא הביעו:

```python
from format_parser import parse_file

# טעינה מכל פורמט
topology = parse_file('network.yaml')
topology = parse_file('network.json')
topology = parse_file('network.xml')
```

זה אומר שלא היה לי צורך לכתוב כלים נפרדים לכל פורמט. כלי אחד לכל הפורמטים.

**שכבה 2: גנראטורים הספציפיים לפרוטוקול**

אחרי זה, בניתי 12 גנראטורים מיוחדים, כל אחד מטפל בפרוטוקול ברשת שונה:

- ospf_pathmaker.py (ניתוב OSPF)
- bgp_conductor.py (ניתוב BGP)
- eigrp_catalyst.py (ניתוב EIGRP)
- static_anchor.py (מסלולים סטטיים)
- asa_shield.py (כללי חומת אש)
- nat_portal.py (NAT/PAT)
- vlan_weaver.py (תצורת VLAN)
- dhcp_allocator.py (הגדרת DHCP)
- hsrp_sentinel.py (יתירות)
- ssh_locksmith.py (אבטחת SSH)
- ip_architect.py (ניהול IP)
- cidr_architect.py (חישובי תתי-רשת)

כל אחד מהם לוקח קלט פשוט ב-YAML/JSON/XML ויוצר את פקודות Cisco IOS בפועל שצריך.

## 4.4 topology_composer.py: שינוי המשחק

אחרי זה בניתי את הכלי הראשי: topology_composer.py. זה היה הכלי שבאמת חסך לי זמן.

אתה מגדיר את כל הרשת שלך בקובץ YAML:

```yaml
devices:
  - name: Router1
    type: Router
    interfaces:
      - id: 0/0
        ip: 192.168.1.1
        mask: 255.255.255.0
        protocol: ospf
        area: 0
  - name: Router2
    type: Router
    interfaces:
      - id: 0/0
        ip: 192.168.2.1
        mask: 255.255.255.0
        protocol: ospf
        area: 0

links:
  - source: Router1:0/0
    target: Router2:0/0
```

אחרי זה אתה מריץ:

```bash
python3 topology_composer.py --file network.yaml --output commands.txt
```

וזה יוצר סט מלא של פקודות Cisco IOS מוכנות להדבקה:

```
configure terminal
hostname Router1
interface GigabitEthernet0/0
 ip address 192.168.1.1 255.255.255.0
 no shutdown
exit
router ospf 1
 network 192.168.1.0 0.0.0.255 area 0
exit
```

במקום להקליד 200+ פקודות ידנית (שזה לוקח 3-4 שעות), אתה פשוט מעתיק ודבק מקובץ הפלט. זמן כולל: 15-20 דקות כולל הגדרה.

## 4.5 ניסיון לבנות Option B: יצירת קבצי .pkt ישירה

אחרי שקיבלתי את topology_composer.py לעבוד, החלטתי לנסות משהו יותר שאפתני: האם אני יכול ליצור קבצי Packet Tracer .pkt ישירות? זה היה מחסל אפילו את הצעד הידני של העתקת פקודות לתוך ה-GUI.

חקרתי את פורמט קובץ .pkt. מתברר שהם קבצים בינאריים עם:
- 4 בתים Header (גודל XML לא מדחוס)
- Payload מוצפן ב-XOR
- דחיסה ב-zlib

אז בניתי את pt_file_builder.py לטיפול בזה. הקוד עבד מבחינה טכנית:

```python
builder = PTFileBuilder(topology_dict)
builder.save('output.pkt')
```

אבל היה בעיה: כשניסיתי לפתוח את הקבצים שנוצרו ב-Packet Tracer 8.2.2, זה דחק אותם עם "Unable to open file. The file was not saved correctly."

בילינו המון זמן בדיבוג של זה. מתברר שפורמט .pkt שחיזרנו (מ-ptexplorer, כלי מ-2012) היה ל-PT 5.x, לא ל-PT 8.2.2. סיסקו שינתה את אלגוריתם ההצפנה עבור 8.2.2, והוא לא מתועד בשום מקום ציבורי.

ניסיתי הכל:
- וריאציות שונות של מפתח XOR
- פירוק zlib ישיר
- ניתוח entropy של הקובץ
- שימוש ב-Wine להריץ את PT ולהוציא קבצים

כלום לא עבד. ההצפנה של PT 8.2.2 היא קניין פרטי של סיסקו ואנחנו לא יכולים להחזיק אותה בלי קוד המקור של סיסקו.

## 4.6 כלים עזר

בזמן שניסינו לתקן את Option B, בנינו שני כלים עזר:

**pt_file_inspector.py** - כלי לניתוח קבצי .pkt:

```bash
python3 pt_file_inspector.py Core.pkt
```

זה מראה גודל קובץ, יחס דחיסה, ומנסה להוציא ולפרוש את ה-XML בתוך.

**pt_debug.py** - כלי דיבוג יותר מתקדם שמנתח את המבנה הבינארי בפירוט.

הכלים האלה עובדים בסדר לניתוח, אבל הם לא יכולים לפתור את בעיית ההצפנה.
