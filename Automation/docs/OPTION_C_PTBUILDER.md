# Option C: PTBuilder Scripting - The Breakthrough Solution

## Status: ✅ Production Ready (New Approach)

## What is Option C?

Instead of trying to reverse-engineer the .pkt binary format or directly generate Packet Tracer files, **Option C uses Packet Tracer's built-in PTBuilder scripting interface**. This is the officially supported way to programmatically create topologies in Packet Tracer.

## How It Works

### The Concept

```
YAML Topology → pt_scriptable_builder.py → PTBuilder JavaScript → Paste in PT → Save .pkt
```

1. Define your topology in YAML/JSON/XML (same as Option A)
2. Run: `python3 pt_scriptable_builder.py network.yaml --output topology.js`
3. Open Packet Tracer
4. Go to: **Extensions → Builder Code Editor**
5. Copy/paste the generated JavaScript
6. Click **Run**
7. PT builds your entire topology
8. Click **File → Save** to save as .pkt

## Usage Examples

### Basic Network (2 Routers)

```bash
python3 pt_scriptable_builder.py simple_topology.yaml --output my_lab.js
```

Output PTBuilder script:
```javascript
// PTBuilder Script - Generated by Keystone Automation
// ===== Add Devices =====
addDevice("R1","2911",100,100);
addDevice("R2","2911",350,100);

// ===== Add Links =====
addLink("R1","GigabitEthernet0/1","R2","GigabitEthernet0/1","straight");
```

Then in PT:
1. Copy the script
2. Extensions → Builder Code Editor
3. Paste and Run
4. Done! Topology is built.

```bash
  --output enterprise_lab.js \
  --include-config
```

This generates both:
- PTBuilder JavaScript for topology creation
- Commented IOS configuration commands for reference

## Input Topology Format

Same YAML as Option A, but links are now optional:

```yaml
devices:
  - name: Router1
    type: Router
  
  - name: Router2
    type: Router
  
  - name: Switch1
    type: Switch

links:
  - source: Router1:0/0
    target: Router2:0/0
  
  - source: Router1:0/1
    target: Switch1:0/1
```

Supported device types:
- Router (maps to 2911)
- Switch (maps to 2960-24TT)
- Firewall/ASA (maps to ASAv)
- PC (maps to PC-PT)
- Server (maps to Server-PT)
- Hub
- Cloud

## Technical Details

### PTBuilder API Functions Used

```javascript
addDevice(name, model, xPos, yPos)
// Adds a device to the topology
// name: string (device identifier)
// model: string (Cisco model like "2911", "2960-24TT", "PC-PT")
// xPos, yPos: integers (screen coordinates)

addLink(source, srcPort, target, tgtPort, linkType)
// Connects two devices
// linkType: "straight", "curved", etc.
```

### Port Naming Normalization

Input → Cisco PT Format
```
0/0 → GigabitEthernet0/1
0/1 → GigabitEthernet0/2
g0/0 → GigabitEthernet0/1
f0/0 → FastEthernet0/1
inside → GigabitEthernet0/1 (for firewalls)
outside → GigabitEthernet0/2
dmz → GigabitEthernet0/3
```

## Step-by-Step Example

### 1. Create YAML file (example_lab.yaml)

```yaml
devices:
  - name: R1
    type: Router
  - name: R2
    type: Router
  - name: PC1
    type: PC

links:
  - source: R1:0/0
    target: R2:0/0
  - source: R1:0/1
    target: PC1:0
```

### 2. Generate PTBuilder script

```bash
python3 pt_scriptable_builder.py example_lab.yaml --output lab.js
```

### 3. Get the JavaScript

```javascript
// PTBuilder Script - Generated by Keystone Automation
addDevice("R1","2911",100,100);
addDevice("R2","2911",350,100);
addDevice("PC1","PC-PT",600,100);

addLink("R1","GigabitEthernet0/1","R2","GigabitEthernet0/1","straight");
addLink("R1","GigabitEthernet0/2","PC1","GigabitEthernet0/1","straight");
```

### 4. In Packet Tracer

- Open Packet Tracer
- Extensions → Builder Code Editor
- Clear any existing code
- Paste the JavaScript
- Click "Run" button
- Watch topology build automatically
- File → Save → Save as lab.pkt

### 5. Done!

Your .pkt file is saved with the complete topology.

## Troubleshooting

**Problem**: "Builder Code Editor not found"
- **Solution**: PTBuilder is an extension. Check Extensions menu. May need to be enabled in Cisco Packet Tracer settings.

**Problem**: Script runs but no devices appear
- **Solution**: Check device models in generated JavaScript. Ensure they match Cisco PT's internal names.

**Problem**: Links don't connect
- **Solution**: Verify port names are correct for each device model. Some models have different port names.

**Problem**: Error about model not found
- **Solution**: The device type may not be available in your PT version. Try substituting with a similar model.
