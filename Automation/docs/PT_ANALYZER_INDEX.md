## 📁 Script Files

### pt_analyzer.js
**What it does**: Runs inside Packet Tracer to extract configs
**How to use**:
1. Extensions → Scripting → Edit File Script Module
2. Paste the entire contents of pt_analyzer.js
3. Click Run
4. Copy the output

**Output format**: Formatted device list + running configs

### pt_config_parser.py
**What it does**: Converts raw Cisco configs to YAML/JSON
**How to use**:
```bash
python3 pt_config_parser.py configs.txt --yaml
python3 pt_config_parser.py configs.txt --json
```

**Generates**: Editable topology definitions

## 🎯 Common Tasks

### Task: Extract an existing topology
1. Open topology in PT
2. Run pt_analyzer.js
3. Copy output to configs.txt
4. Run pt_config_parser.py

**Time needed**: 5-10 minutes

### Task: Modify extracted topology (change IPs, hostnames)
1. Open generated configs_topology.yaml
2. Edit with any text editor
3. Change IPs, hostnames, etc.
4. Save

**Time needed**: 5-15 minutes

### Task: Rebuild modified topology in PT
1. Run topology_composer.py on modified YAML
2. Copy generated CLI commands
3. Use main.js to inject into PT
4. Verify topology

**Time needed**: 10-30 minutes

### Task: Share topology with someone else
1. Run pt_analyzer.js
2. Copy output
3. Send the YAML file generated by pt_config_parser.py
4. They can modify and rebuild

**Time needed**: 5-10 minutes

## 🚀 Getting Started (Right Now)

**Minimum steps to try it:**

1. **Get a topology**
   - Open any existing .pkt file in Packet Tracer
   - Or create a simple one (2 routers)

2. **Extract configs**
   - Extensions > Scripting > Edit File Script Module
   - Paste pt_analyzer.js
   - Click Run

3. **Copy output**
   - Select all (Ctrl+A)
   - Copy (Ctrl+C)
   - Paste to configs.txt

4. **Parse to YAML**
   ```bash
   python3 pt_config_parser.py configs.txt --yaml
   ```

5. **View generated YAML**
   ```bash
   cat configs_topology.yaml
   ```

**Total time**: 10 minutes

## ❓ FAQ

**Q: Can I edit the YAML file?**
A: Yes! Change anything: hostnames, IPs, OSPF IDs, VLANs, etc.

**Q: Do I need to modify the scripts?**
A: No, they work as-is. The YAML is what you edit.

**Q: Can I extract multiple topologies?**
A: Yes, run analyzer on each topology separately.

**Q: Can I merge topologies?**
A: Yes, manually combine the YAML files.

**Q: What if a device doesn't extract?**
A: Some device types don't have CLI. See README troubleshooting.

**Q: How do I deploy back to PT?**
A: Use main.js with the new CLI commands generated by topology_composer.py
