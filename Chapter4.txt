פרק 4: אוטומציות ותכנות במהלך הפרויקט

====================================================================================

מבוא

במהלך פיתוח תשתית ענן מקיפה עבור SOYMSA, נתקלנו בחסם קריטי: תיקוף ידני של עשרות התקנים ברשת היה לוקח שבועות. 
בחרנו להשקיע בפיתוח ארסנל של כלים אוטומטיים בשפת Python, המאפשרים ניהול חכם של רשת כוללת, מחולל פקודות CLI, 
ואוטומציה של יצירת קבצי סימולציה. הפרק הזה מתאר את התפלצים, התוספות ותהליכי הפיתוח שהנעו את הפרויקט קדימה.

from format_parser import parse_file, save_file

זה פתר בעיה גדולה: משתמשים שונים מעדיפים קבצים שונים. דרך זו, אנחנו תומכים בהם כלם.

4.2 topology_composer.py - מחלל קומנדות CLI

====================================================================================

הכלי השני שפיתחנו היה topology_composer.py. זה הכלי שהשתנה הכל עבורנו.

דוגמה:

```yaml
# network_example.yaml
devices:
  - name: Router1
    type: Router
    interfaces:
      - id: 0/0
        ip: 192.168.1.1
        mask: 255.255.255.0
        protocol: ospf
        area: 0
  - name: Router2
    type: Router
    interfaces:
      - id: 0/0
        ip: 192.168.2.1
        mask: 255.255.255.0
        protocol: ospf
        area: 0

links:
  - source: Router1:0/0
    target: Router2:0/0
```

הפעלה:

```bash
python3 topology_composer.py --file network_example.yaml --output commands.txt
```

התוצאה: קובץ commands.txt שמכיל 150-200 פקודות Cisco IOS מוכנות:

```
!===== Router1 Configuration =====
configure terminal
hostname Router1
interface GigabitEthernet0/0
 ip address 192.168.1.1 255.255.255.0
 no shutdown
!
router ospf 1
 network 192.168.1.0 0.0.0.255 area 0
!===== Router2 Configuration =====
configure terminal
hostname Router2
...
```

הערך שלו לא יכול להיות מוערך יותר: במקום להקליד 200 פקודות, משתמש פשוט מעתיק ודבק. זה חוסך 3-4 שעות עבודה.

4.3 pt_file_builder.py - יצירת קבצים בינארים .pkt

====================================================================================

בשלב מתקדם של הפרויקט, שאלנו את עצמנו: "האם אנחנו יכולים ליצור קבצי .pkt ישירות?"

התשובה הייתה מורכבת. ספרנו את המבנה של קובץ .pkt:

1. Header: 4 בתים (גודל XML לא דחוס, big-endian)
2. Payload: XOR-encrypted עם מפתח דינמי
3. Compression: zlib

```python
from pt_file_builder import PTFileBuilder

builder = PTFileBuilder(topology_dict)
builder.save('output.pkt')
```

זה עבד לחלקית - הקבצים שנוצרו היו בעלי מבנה חוקי מבחינה פנימית, אך Packet Tracer 8.2.2 
דחק אותם בשגיאה "Unable to open file. The file was not saved correctly."

הבעיה הייתה: הפורמט שחיזרו עבורנו היה מבוסס ptexplorer (2012), שתיאר כנראה את הפורמט של PT 5.x, 
לא PT 8.2.2. הקבצים הממשיים של סיסקו השתמשו באלגוריתם הצפנה שונה לגמרי.

4.4 כלי עזר: pt_file_inspector.py ו- pt_debug.py

====================================================================================

כדי להבין את הבעיה, בנינו שני כלי ניפוי (Debugging):

pt_file_inspector.py - ניתוח קבצים:

```bash
python3 pt_file_inspector.py Core.pkt
```

תוצאה:
```
File: Core.pkt
Size: 47000 bytes
Header (uncompressed XML size): 89234 bytes
Payload (compressed): 47000 bytes
Compression ratio: 52.6%

✓ Successfully decrypted and decompressed
✓ XML is valid
```

pt_debug.py - ניתוח עמוק יותר:

```bash
python3 pt_debug.py Core.pkt --hex 10
python3 pt_debug.py Core.pkt --xml --pretty
```

כלים אלה הוכיחו שהם בעלי ערך אדיר בחקירת הסוגיות.
